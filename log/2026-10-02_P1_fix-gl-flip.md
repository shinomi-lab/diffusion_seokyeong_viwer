# 開発ログ: 修正 — ノードとエッジの位置のずれ

- 日付: 2026-10-02
- 段階: P1 の不具合修正
- 前段階: `log/2026-10-02_P1_web.md`

## 報告
ユーザーが実際に動かして、「ネットワーク画面を動かすと、ノードとエッジが分離する」と報告。確認したところ、止めた後もずれたまま、環境は 100random・Retina の Mac。

## 原因
頂点シェーダ（`web/src/render/shaders.ts`）が y を反転していた。NDC もワールドも y は上向きなので反転は不要で、反転が必要なのは y が下向きの Canvas2D（エッジ・リング・強調・クリック判定）だけ。WebGL のノードだけが画面中心で上下ミラーされ、縦にパンするほど逆方向にずれていた。

## 修正と検証
1. 先にテストを作って不具合を再現した: `npm run e2e:align`（開発時のみの `window.__glProbe` で WebGL のピクセルを読み、Canvas2D と同じ式の位置と比べる。DPR 1・2、初期表示・縦横パン・ズームイン/アウト）。修正前は **23 件不一致**（初期表示で 100 ノード中 85 個）、縦パンでは上下ミラー位置にノードがあることも確認。
2. シェーダの 1 行を修正（`vec2(u_zoom, -u_zoom)` → `u_zoom`）。
3. 修正後は **全件一致**（DPR 1・2、全ノード）。Retina でパン後のスクリーンショットを目視し、エッジがノードに接し、リングの中心が IP に合っていることを確認。IP を見た目の位置でクリックして選択できる。
4. `npm run build`・`npm test`（10 件）が通ることを確認。

## 反省（過去のログの訂正）
`log/2026-10-02_P1_web.md` に「ノードのクリックが当たらないように見えた → テストの座標のずれ」と書いたが、**誤り**。実際はこのバグ（WebGL の描画位置が 2D の計算位置と約 10px ずれていた）だった。計測値のずれを見たときに原因を詰めず、テストの問題と決めつけた。位置の一致を自動で確認する `e2e:align` で、今後は検出できる。
