実装計画

  1. トークンの拡張（spec/ui-tokens.json）: kinds・highlight・series に dark の組を追加（fill / fillDark のように対で持つ）。chrome.dark・background.dark・rings・edges を上の値に。読み込み側（web/src/tokens.ts・desktop/src/tokens.rs）はテーマに応じて選ぶ関数を 1 つ用意し、色を使う所はそれを通す。
  2. 既定のテーマ: OS の設定に従う（現状どおり）。ダークで参照の雰囲気、ライトは同じ規則の濃い色。
  3. Web: WebGL の色（render/gl.ts）、Canvas の重ね描き（render/overlay.ts）、ミニマップ・凡例（NetworkView.tsx）、時系列（panels/Plot.tsx: 実線の系列に縦グラデーションの塗り、fillTo = グラフの底）、分岐ツリー（SeriesPanel.tsx）。テーマ切替で WebGL の色を送り直す。
  4. デスクトップ: gpu/mod.rs の Uniforms にテーマ別の色、panels/charts.rs・detail.rs の系列色、panels/legend.rs の凡例、panels/network.rs の輪・選択色、theme.rs のアクセント。egui_plot には面の塗りがあるので（Line::fill）、同じ面グラフ風にする。
  5. 書き出し: PNG・録画は画面と同じ配色。SVG（logic/svg.ts・desktop/src/svg.rs）は資料用の白地とライトの色のまま（印刷・論文向け）。
  6. テスト・確認: 実 GPU のピクセル検証（cargo test -p desktop）と、Web の位置合わせ（npm run e2e:align）は色の判定をトークンから取るよう直す。npm run e2e:p3・e2e:media、前後のスクリーンショット（ライト／ダーク、通常／比較）、色覚シミュレーションの再計算、--bench とフレーム時間の比較。

性能への配慮

  • 色の値を変えるだけで、描画の処理（頂点数・パス数・シェーダ）は増えない。
  • 面グラフの塗りは時系列グラフ（数十点）だけで、ネットワーク図には付けない。ノードの光彩（参照の柔らかい光）は、毎フレームのぼかしが重いので入れない。代わりに IP だけ白い縁を付けて目立たせる。
  • backdrop-filter（すりガラス）は引き続き使わない。

変えないもの

配置・パネル寸法・文言・操作・ノードの形と大きさ・凡例の項目・既存のテストの判定内容。

判断が必要な点

  • データの色を Okabe–Ito から変えることになる（要件の「色覚に配慮した配色」は上の検証で満たす）。設計書の 11.1 の色表を更新する。
  • ライトモードも参照の色調（濃い版）に揃えるか、ライトは現在の Okabe–Ito のまま残すか。
